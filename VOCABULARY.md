## Architecture

| Term | Definition |
|---|---|
| **Cognitive Foundation** | The architectural principle: the database is the agent's cognitive substrate, not its storage layer. It maintains knowledge over time through structured memory and lifecycle management. |
| **Unified Data Substrate** | A single ACID-compliant cluster that serves as both the operational data store and the agent's memory. No separate vector store, no cache, no warehouse. One transaction boundary. |
| **Data Plane** | Domain-specific operational data: telemetry, transactions, events, and ground truth catalogs. The raw material the agent reasons against. |
| **Context Plane** | Three-tier agent memory that persists across sessions. Episodic, semantic, and procedural memory — maintained by the five custodial duties. |
| **Agent Layer** | Stateless LLM with tools. Disposable and ephemeral. The platform remembers on its behalf. |
| **Action Layer** | The architectural tier above the read layer where agents write back to durable memory, confidence drives routing, and every decision is reconstructable in a single query. The read layer (analytics, BI, MCP-on-existing-data) is solved; the action layer is not. This is TiDB's exclusive positioning territory. Requires ACID writes, vector search, and durable memory in the same transaction boundary — a database problem, not an analytics problem. |
| **Frankenstack** | The bolted-together collection of separate services (OLTP + vector store + session cache + analytics warehouse + glue code) that most teams have assembled for agentic workloads. Was tolerable at subsidised inference rates; becomes structurally unviable at market-rate inference because the glue between systems becomes the dominant cost. Use verbally in talks; do not put on slides (the visual is the receipt comparison). |
| **Domain Adapter** | The pluggable configuration that defines a use case: schema mapping, window/aggregation config, anomaly weights, text banding rules, and seed catalog. The only part you write per domain. |

## Three-Tier Memory

| Term | Definition | Typical implementation |
|---|---|---|
| **Episodic Memory** | Time-stamped records of what happened — interactions, investigations, decisions, outcomes. The agent's experiential history. | `agent_reasoning`, `chat_history` |
| **Semantic Memory** | Learned knowledge that persists across sessions and agents. Facts, patterns, and rules extracted from experience. Scoped (global, site, model, entity). | `fleet_memory`, `sales_knowledge`, knowledge base tables |
| **Procedural Memory** | Learned workflows and execution strategies. How the agent acts on what it knows — investigation playbooks, escalation logic, remediation procedures. | Branching + RCA logic, agent directives, escalation rules |

## Five Custodial Duties

| Duty | Definition |
|---|---|
| **Write Control** | Only confirmed outcomes are persisted. Working reasoning is ephemeral. Memory grows at O(investigations), not O(reasoning steps). |
| **Deduplication** | Near-duplicate memories (cosine distance < 0.15) are merged rather than accumulated. One strong memory with high evidence count, not ten weak duplicates. |
| **Reconciliation** | New evidence that contradicts existing memory auto-supersedes the older conclusion. `superseded_by` links the chain. Truth evolves, not accumulates. |
| **Confidence Decay** | Memories that aren't reinforced lose confidence over time (e.g., 5% monthly). Below a threshold (e.g., 0.30), auto-deprecated. Stale knowledge fades rather than poisoning. |
| **Compaction** | Periodic re-clustering merges memories that have drifted close together. Evidence counts consolidated. The knowledge store stays lean. |

**Framing note:** The five duties are the hygiene, not the moat. The substrate is the moat. Title them "Five duties the substrate makes operational" in presentations — this emphasises that the duties only work because they run as SQL inside a single cluster.

## Key Mechanisms

| Term | Definition |
|---|---|
| **Context Assembly** | Budget-constrained function that builds the agent's prompt from priority-ordered sources. Runs before the model is invoked. Zero LLM calls. Pure SQL. The model never decides what to remember — the platform decides for it. |
| **Routing Layer** | After context assembly, code (not the model) inspects the top fleet memory match. If confidence and similarity gates are passed, the investigation routes to a Haiku shortcut path (3 tool rounds) instead of the default Sonnet exploration path (15 rounds). The cognitive foundation drives a model-selection decision, not just textual context. |
| **Shortcut Path** | The cheap, fast routing branch: Haiku model + 3 tool rounds + skipped classify call. Fires when the cognitive foundation has a high-confidence pattern match (`confidence ≥ 0.85`, `similarity ≥ 0.55`). Produces ~75% dollar-cost reduction and ~40% latency reduction vs the explore path on production-scale fleets. |
| **Explore Path** | The default routing branch when no high-confidence match exists: Sonnet model + 15 tool rounds. Used on cold clusters or when the trigger doesn't match a stored pattern. The legacy code path before the routing layer was added. |
| **Warm-up Period** | The number of dispatches a fresh cluster needs before routing fires reliably. Empirically ~15-25 dispatches: enough for `consolidation_job` and stable agent writes to converge on canonical patterns that consistently surface as top vector matches. Production clusters with weeks of accumulated memory skip this entirely. |
| **Hybrid Search** | Vector cosine similarity + FULLTEXT keyword matching in a single SQL query. Vectors catch meaning ("salt corrosion" ≈ "coastal earth leakage"). Keywords catch identifiers (error codes, firmware versions). |
| **Semantic Banding** | Converting raw metrics to natural language before embedding. `voltage_stddev=12.3` → "high voltage variance, possible supply sag." Dramatically improves vector recall. |
| **Human-in-the-Loop** | The human validates, not executes. Serverless branching enables safe autonomy: agent proposes → branch validates → human approves → promote to production. |

## Problem Framing

| Term | Definition |
|---|---|
| **Memory Wall** | The infrastructure problem caused by stateless models on fragmented stacks. Not a model limitation — an architecture limitation. The headline problem the cognitive foundation solves. Use this as the named problem in all external content. |
| **Load-bearing** | Describes the audience's current state: agents woven into production operations, making decisions, touching customers, can't be ripped out. Use in opening delivery to name where the audience already is, before introducing what needs to change. Unlocks the vocabulary chain: load-bearing → foundation → substrate → cognitive foundation. |
| **Token Tax** | **Deprecated as headline framing for external content.** Narrow technical definition retained: the runtime cost of re-assembling investigation context from scratch on every invocation. `assemble_context` eliminates this specifically — it runs in <50ms with zero LLM calls. **Do not use as the primary economic argument.** Per-investigation API spend is governed by the routing layer, not by context assembly. The pre-evidence framing ("quadratic context cost") was empirically incomplete — see AGENT_LIFECYCLE.md §5. Lead with capability; cost is downstream. |
| **Agentic Tax** | **Retired.** Was used in the March 2026 GTM Playbook to describe engineering overhead of fragmented stacks. Replaced by Memory Wall (the architectural framing) and Frankenstack (the infrastructure it describes). Do not use in new content. |
| **State Explosion** | The scaling problem when N users × M agents × Z branches creates thousands of concurrent memory contexts. Traditional databases assume one app, one database, predictable load. Agent workloads are the opposite. |
| **Subsidy Correction** | The economic pressure that makes the timing argument urgent. AI labs are currently losing money on every seat (~$8 compute per $1 subscription at Anthropic). This subsidy is deliberate — a land-grab before the IPO window. The repricing trigger is the IPO calendar. GitHub repriced Copilot to usage-based billing on June 1, 2026 as early evidence. The frankenstack was tolerable at subsidised rates; at market rates, the glue between systems becomes the dominant cost. Use verbally in talks; attribute underlying facts to primary sources (GitHub announcement, KPMG analysis), not to secondary articles. Never say "bubble" — use "repricing" or "correction." |

## Capability vs Cost

| Term | Definition |
|---|---|
| **Capability Multiplier** | The irreducible value of the cognitive foundation. Cluster recognition, recurrence detection, cross-charger evidence chains — outputs that stateless agents on identical telemetry literally cannot produce. Universal across cluster states; doesn't require routing or warm-up. This is the lead argument in all positioning — it's the one no competitor can pattern-match. |
| **Cost Reduction** | The downstream effect of routing high-confidence matches to the Haiku shortcut path. Operates in three measured dimensions (tokens, dollars, latency) that don't move together. The dollar reduction is the strongest claim (~75% on production fleets) because it's driven by Sonnet→Haiku model substitution, not just token volume. **Always position after capability, never before.** |
| **Confidence Delta** | The measured difference in agent output quality between cold clusters (0.72–0.78) and warm clusters (0.93–0.99) on identical telemetry. The business consequence: high confidence → agent can act (close a ticket, trigger remediation, send an alert with defensible diagnosis); low confidence → agent can only suggest. The delta between acting and suggesting is the delta between retention and churn, between SLA compliance and SLA breach. |

## Six Business Outcomes

The action layer produces six measurable business outcomes. Use this mapping to translate technical capabilities into CFO language.

| Outcome | Definition | Action layer capability |
|---|---|---|
| **Monetisation** | Agents-as-a-service on a unified tenant substrate. Branching + tenant isolation + elastic scale-to-zero = viable per-tenant economics. | Serverless branching, vectors-as-datatype, RU metering |
| **Increased Margin** | Lower the cost of operational state via routing + confidence. High confidence → cheaper model → same capability. The agent knows it knows, so it doesn't ask for help. | Routing layer, confidence calibration, semantic memory |
| **Modernisation** | Automated investigation workflows replacing manual triage. Machine-speed pattern matching via hybrid search. | HTAP, hybrid search, context assembly |
| **Auditability** | Single-query RCA. Reconstruct exactly what the agent saw when it decided. One SQL, one system, one truth. | ACID transaction log, unified substrate |
| **Time to Resolution** | Wall-clock improvement via routing-based model selection. Shortcut path: 48.6s vs explore path: 80s. | Routing layer, shortcut path |
| **Compliance** | EU AI Act / GDPR by architecture, not by project. Single transaction log. Right to erasure = one SQL command. | ACID, unified substrate, single txn log |

**The bridging line:** "Six capabilities. Six business outcomes. None of them exist without managed memory. None of them work on a frankenstack."

## Competitive Framing

Do not name competitors in prepared external content. Frame by category.

| Category | Their claim | Our reframe |
|---|---|---|
| **Memory services** (Mem0, Zep, Letta) | "We add memory to your agents" | Memory services are external to your database — separate consistency model, separate sync, separate audit. Memory as a database capability shares the ACID boundary with your operational data. One system vs two. |
| **Vector-only databases** (Pinecone, Weaviate) | "We are the best vector database" | Vectors without relational context are floating numbers. The query your agent needs — "show me all confirmed diagnoses semantically similar to this anomaly for chargers at this site" — requires a join between vector index and transactional data. That join cannot cross system boundaries without losing consistency. |
| **Cloud RDBMS** (Aurora, AlloyDB) | "We have AI features and vector bolt-ons" | Bolt-on vector search is a second workload type on a system designed for one. When your primary user is an agent running millions of ephemeral contexts, the scaling model breaks. |
| **Analytical / Lakehouse** (Snowflake, Databricks) | "We handle all your data at scale" | They handle the read layer. Agent workloads require sub-second transactional writes alongside vector similarity in the same transaction boundary. Warehouse latency is measured in seconds; agent decision loops in milliseconds. |

**The universal reframe:** "The read layer is solved. The action layer requires a different substrate — one where the write-back, the memory lifecycle, and the audit trail share a single transaction boundary."
